# Рабочее меню SBG Coffee

Источник — три карточки владельца: `SBG coffee menu with updated prices.png`,
`Autumn SBG Coffee Seasonal Menu.png` и `Barista cheat sheet with lavender frothing note.png`.
26 октября 2026 владелец уточнил: все чаи по 400 мл; каждый сироп стоит 100 ₸;
любую из перечисленных добавок можно выбрать к любому напитку по одной порции.
Данные ценника отделены от внутренних рецептур бариста.

## Товары и цены

Все цены — целые KZT. S = 250 мл, L = 400 мл.

| Товар | S | L |
|---|---:|---:|
| Американо | 600 | 800 |
| Капучино | 800 | 1300 |
| Латте | 800 | 1300 |
| Горячий шоколад | 800 | 1200 |

| Чай (400 мл) | Цена |
|---|---:|
| Чёрный чай | 250 |
| Чай с лимоном | 350 |
| Чай с малиной | 400 |
| Медово-имбирный чай | 450 |
| Цитрусовый уют | 600 |

Для «Цитрусового уюта» на карточке указан состав: апельсин, лимон, имбирь.

Сезонное меню: тыквенный капучино, тыквенный латте, обычный раф,
тыквенный раф и лавандовый раф — каждый **250 мл за 1000 ₸**.
Рецепт рафа L есть в памятке, но его цены нет: этот вариант не включён в продажу.

Чокопай — **200 ₸ за штуку**, шесть вариантов вкуса: обычный, клубника,
апельсин, вишня, манго, чёрная смородина. Объём к штучному товару неприменим.

Добавки по **100 ₸**: лимон, имбирь, молоко; сиропы карамель, солёная карамель,
ваниль, попкорн, гранат, мохито. **Мёд — 200 ₸**.
Порция добавки оплачивается на каждую единицу напитка: два напитка с мёдом
стоят `2 × (цена напитка + 200)`. Чокопай добавок не имеет.
Тыквенный и лавандовый сиропы используются в рецептах, но отдельно на ценнике
не продаются. Объём порций платных добавок не указан и не выдумывается.

Итого: 15 товаров (14 напитков и Чокопай), 24 варианта (18 напитков + 6 вкусов),
10 добавок. Существующие IDs шести первоначальных напитков и их вариантов
сохранены, включая `pumpkin` (тыквенный латте) и `lavender` (лавандовый раф).

## Совместимость приложения и API

`GET /api/v1/catalog/products` сохраняет прежний контракт и возвращает доступные
напитки без добавок. Он не возвращает десерты и новые ключи изображений.
`GET /api/v2/catalog/products` возвращает полное меню с `addons` у каждого
товара, категорией `dessert`, ключами изображения `tea`/`dessert` и `volumeMl: null`
у вариантов десертов. У напитков объём положительный. Цена варианта не включает
выбираемые добавки; каждая добавка имеет собственные `id`, `name`, `priceKzt`.
Неизвестные query-параметры отклоняются; API не обещает неизменность цены до checkout.

Новые таблицы Dessert/DessertVariant и Addon не меняют прежние Product/ProductVariant.
Поэтому миграция и импорт сохраняют чтение предыдущим API; откат контейнера
оставляет новые таблицы/данные на месте. Общий namespace идентификаторов
проверяется импортом в обеих группах таблиц, включая недоступные записи.

Новый клиент использует v2 и отдельный кеш v2. Старый кеш каталога не считается
ответом v2. Старые корзины и история читаются с пустым набором добавок;
новые строки сохраняют состав добавок. Повтор заказа заново проверяет доступность.
Изменение цены добавки учитывается при повторном получении каталога перед
демо-checkout и требует нового подтверждения суммы. При недоступности API
кеш остаётся только для просмотра; автоматического перехода на mock нет.

Профиль, история заказов и бонусы остаются локальными демонстрационными данными.
Серверный каталог не означает принятия заказа кофейней.

## Импорт рабочего каталога

Импорт не является `db:seed`: seed по-прежнему только для dev/test и не
запускается в production. Рабочий manifest находится в
[real-menu.ts](../apps/api/prisma/real-menu.ts), CLI — в
[import-menu.ts](../apps/api/prisma/import-menu.ts).

После `npm run build:api` и миграций, с DATABASE_URL нужной базы:

```sh
npm run db:import-menu --workspace @sbg/api
npm run db:import-menu --workspace @sbg/api -- --apply
```

Первая команда только показывает план; вторая применяет его одной транзакцией.
Повторный запуск не создаёт дублей. Данные проверяются до записи; конфликт IDs
или переназначение варианта другому товару отменяет весь импорт. Импорты
сериализуются advisory lock в PostgreSQL. Не перечисленные записи сохраняются;
для скрытия управляемой записи нужен явный `available: false` в manifest.
Не запускайте демонстрационный seed после рабочего импорта: он перезаписывает
цены своих шести товаров.

Для проверенного альтернативного JSON manifest используйте `--manifest /absolute/menu.json`
с обеими командами. Формат: `version`, `products`, `desserts`, `addons`; каждый объект
содержит явную доступность. Схема и пример встроенного manifest находятся в
`real-menu.ts`. Сначала просмотрите diff и dry-run именно этого файла.

На сервере сначала сделайте резервную копию штатным `infra/scripts/backup.sh`,
затем доставьте прошедший CI образ по digest. Миграции выполняются обычным deploy.
Запускайте импорт из того же образа и его release Compose:

```sh
deployment_dir=/opt/sbg-coffee
export API_IMAGE=$(cat "$deployment_dir/state/current-image")
compose_file=$(cat "$deployment_dir/state/current-compose")
docker compose --project-name sbg-coffee-production \
  --env-file "$deployment_dir/production.env" -f "$compose_file" \
  run --rm --no-deps api npm run db:import-menu --workspace @sbg/api
# После проверки плана:
docker compose --project-name sbg-coffee-production \
  --env-file "$deployment_dir/production.env" -f "$compose_file" \
  run --rm --no-deps api npm run db:import-menu --workspace @sbg/api -- --apply
```

После применения проверьте `/health`, обе версии каталога и повторный dry-run.
Новый мобильный bundle нужен для сладостей/добавок; доставка backend сама по себе
не обновляет установленное приложение.
